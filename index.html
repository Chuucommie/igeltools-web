02 / Agents

Built for agents as well as people.

Every app in the suite is designed to be driven through a local Model Context Protocol server, so an assistant can do what you can do — with the same validation and the same local-first rules.

MCP

One server per app

Each app exposes its own MCP server locally. No shared cloud account, no relay and no remote listener: the agent talks to the app on your machine.

MCP

Same powers as the window

An agent can read state and ask for the actions the app offers, with the same checks. The tool list is the app's capability list, not a back door.

MCP

Approval stays with you

Tools that change something are marked as such, so the agent host can ask before it installs, restarts or rewrites anything.

Tool schemas, security rules and client setup live in the documentation: Read the MCP docs ↗.

03 / How it is built

Local, native, honest.

Six habits shared by every tool here, whichever machine it talks to.

01

Local first

The TVs are on your network, the server is a box you own, the notes sit in your own iCloud. Nothing takes a detour through a relay of ours.

02

No IgelTools account

Nothing to register. The apps work with the machines and accounts you already have: your Wi-Fi, your SSH key, your iCloud.

03

Native, not wrapped

SwiftUI on Apple platforms, Rust with egui or Tauri on Linux. No web view pretending to be an app.

04

One job per app

Each app solves one problem completely instead of half-solving four. The menu stays short on purpose.

05

Honest about limits

Fire TV is marked Limited, Apple TV is out of scope, the interactive terminal is not wired up yet. The apps say so instead of pretending.

06

Built to last

An app that ships keeps getting fixes. Nothing here is a weekend experiment left to rot.
